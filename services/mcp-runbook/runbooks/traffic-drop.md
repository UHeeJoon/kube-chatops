# 요청 급감 (트래픽이 갑자기 줄거나 0)

이상 탐지 모델의 `rps_drop` 특성이 이 경우를 본다. 오류도 지연도 없이 "조용해지는" 장애라 알림이 늦다.

## 증상

- 초당 요청 수가 평소의 절반 아래로 떨어지거나 0 이 된다. 오류율과 지연은 정상이다.
- 사용자는 접속이 안 된다고 하는데 앱 지표는 깨끗하다.

## 확인

- 요청 수: `sum(rate(http_requests_total{namespace="demo"}[2m]))` 의 추세. 계단처럼 떨어졌는지, 서서히 줄었는지.
- 앞단: WAF(deployment/waf) 파드가 살아 있는지 (`DemoWafDown`). WAF 가 죽으면 바깥 요청이 앱까지 오지 않는다.
- 부하 생성기: `load-gen` 파드 상태. demo 의 평소 트래픽은 대부분 load-gen 이 만든다. 이것이 죽으면 요청이 거의 0 이 된다.
- 막힌 것: WAF 403·429 가 늘었는지 (`waf_blocks`). 정상 요청이 규칙에 걸려 막히면 앱에는 요청이 줄어든 것으로만 보인다.
- 네트워크 정책: 최근 정책 변경으로 들어오는 길이 막혔는지 (`hubble_drop_total{destination_namespace="demo"}`).

## 원인 후보

- 호출하는 쪽(load-gen, 상위 서비스)의 장애.
- 앞단(WAF, 게이트웨이, Cloudflare 터널) 장애.
- 요청 수 제한이나 WAF 규칙의 오탐.
- 네트워크 정책 변경.

## 조치

- 앱을 재시작해도 풀리지 않는다. 요청이 어디서 끊겼는지(호출자 → 앞단 → 앱)를 순서대로 좁힌다.
- load-gen 이 죽었으면 그 파드의 이벤트와 로그를 본다. 시험 환경에서는 실제 사용자 영향이 없으므로 심각도를 낮게 본다.
