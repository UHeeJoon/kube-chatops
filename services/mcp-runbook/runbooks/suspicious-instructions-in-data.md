# 로그나 요청 안에 에이전트를 겨냥한 문장이 있음 (프롬프트 인젝션 시도)

공격자가 요청 경로, User-Agent, 로그에 남는 값에 AI 에게 하는 말을 심어, 조사 보고를 틀리게 만들려는 시도.

## 증상

- Slack 보고서 아래에 `조사한 데이터에 지시처럼 보이는 문장이 있었음` 경고가 붙는다.
- 지표 `agent_injection_suspected_total` 이 늘어난다.
- WAF 로그의 요청 예나 User-Agent 에 영어·한국어 문장이 들어 있다 (보통의 공격 페이로드는 문장이 아니라 코드다).

## 확인

- 어느 도구 결과였나: 경고에 도구 이름이 나온다 (`loki__waf_blocks` 면 막힌 요청, `loki__search_logs` 면 앱 로그).
- 원본: `waf_blocks` 의 출발 IP 와 요청 예. 그 IP 의 다른 요청이 무엇을 노렸는지 함께 본다.
- 보고서가 휘둘렸나: 보고서의 결론(심각도, 원인, 조치 제안)이 원본 지표·로그와 맞는지 사람이 확인한다.

## 판단

- 이런 문장이 있다는 것 자체가 표적 공격의 근거다. 자동 스캐너는 이런 문장을 넣지 않는다. 상대는 여기에 AI 조사가 있다는 것을 안다.
- 차단과 격리는 AI 판단과 무관하게 동작하므로 방어는 유지된다. 위험은 틀린 보고서에 사람이 속는 것이다.

## 조치

- 그 출발 IP 를 Cloudflare 에서 막는 것을 사람에게 권한다.
- 그 보고서의 조치 승인 버튼은 원본을 확인하기 전에는 누르지 않는다.
- 에이전트는 읽기 전용이고 조치는 operator 승인과 고정된 대상 목록을 거치므로, 문장만으로 클러스터가 바뀌지는 않는다.
